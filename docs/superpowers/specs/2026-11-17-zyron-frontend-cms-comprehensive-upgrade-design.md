# ZYRON 外贸网站前台与 CMS 全面升级设计

## 1. 背景与意图

ZYRON 是已上线运行的工业机械外贸网站，包含产品展示、询盘、CRM、实时访客、聊天、媒体库、SEO 与后台认证等真实业务。本次升级的目标不是重建网站，而是在保留现有 URL、产品内容、数据库、询盘和搜索引擎收录的前提下，将当前部分写死的前台与固定模块后台演进为数据驱动、可预览、可发布、可回滚的内容系统。

系统服务于海外 B2B 采购商和 ZYRON 内部网站运营、产品、外贸销售与管理员。前台应优先展示真实机械设备、技术参数、制造与交付能力；后台应让非开发人员能安全维护导航、页面、产品、发货记录、媒体、多语言和 SEO。

## 2. 现有架构与已确认基线

- Next.js 15 App Router、React 19、TypeScript 5、Tailwind CSS 3。
- Prisma 7 和 PostgreSQL，已有正式迁移链路。
- Vercel 托管，使用 `vercel-build` 脚本，构建前生成 Prisma Client。
- 数据库 Session、Argon2 密码、RBAC、审计日志、登录限流已实现。
- 产品、分类、型号参数、Banner、媒体、SEO、询盘 CRM 均使用真实 API 与数据库。
- 媒体使用 S3-compatible 对象存储，不依赖 Vercel 临时文件系统。
- 通用 Page Builder 已有 `SitePage` / `PageVersion`、31 个受 Schema 约束组件、草稿、发布、回滚和三端预览。
- 产品编辑器已有 24 种 `ProductSectionType`，但同类模块不能重复，也不支持递归布局。
- 前台产品详情仍有数据库模块和独立 React 页面两套渲染路径。
- Header、Footer 和多数导航仍是代码静态数组，尚未与后台共用数据源。

## 3. 目标

1. 把前台主导航统一为 HOME、ABOUT ZYRON、PRODUCTS、SUPPORT、CONTACT，保留 Quote Now 与语言入口。
2. 删除导航中的 Buying Guides 和独立 SHOWCASE，将 Customer Cases 替换为 Shipping Highlights，但不删除旧文章或 SEO URL。
3. 建立可由后台管理的导航与页脚数据源，桌面、平板、手机与页脚共用同一发布快照。
4. 建立可视化、模块化、响应式的页面编辑体验，保留草稿隔离、发布快照、版本历史和回滚。
5. 以小型电动剪板机为默认产品模板内容基线，让每个产品可拥有完全独立的结构化页面。
6. 建立 Shipping Highlights 独立内容类型、后台 CRUD、前台列表与详情页，仅发布真实记录。
7. 完善多语言、SEO、重定向、hreflang、图片 alt、结构化数据和 RTL 布局基础能力。
8. 不破坏现有询盘、CRM、WhatsApp、聊天、分析、产品 URL、数据库与搜索引擎收录。

## 4. 非目标与禁止事项

- 不新建独立项目，不替换现有技术栈。
- 不一次性切换所有前台页面或自动转换所有产品。
- 不允许用户注入原始 HTML、JavaScript、未受限 CSS 或任意 iframe。
- 不伪造工厂数据、认证、发货记录、产品参数或客户身份。
- 不复制小鹏的代码、品牌、素材、文案或汽车交易流程，只借鉴长滚动章节节奏与媒体展示逻辑。
- 不在构建时连接或修改生产数据库，不自动运行种子、重置或破坏性迁移。
- 未经单独生产授权，不应用正式数据库迁移，不切换生产域名。

## 5. 方案比较与选择

### 方案 A：渐进式扩展现有 CMS（已选择）

复用现有数据模型、权限、媒体、审计、Page Builder 和产品模块，增加导航、页脚、Shipping Highlights、产品自由页面和本地化能力。所有新内容使用“草稿 + 已发布快照 + 现有内容回退”路径。

优点是对现网影响最小，可分阶段验收和回滚；代价是过渡期会保留新旧两条渲染路径。

### 方案 B：整体替换为新 CMS

一次性迁移全部页面与产品内容，删除旧渲染逻辑。长期代码更简洁，但无法在当前真实内容与 SEO 风险下安全证明数据无损，因此不采用。

### 方案 C：仅改前台视觉和后台菜单

实施速度快，但无法实现真实编辑、发布、回滚、导航联动和发货数据管理，不满足任务，因此不采用。

## 6. 系统设计原则

### 6.1 发布快照优先

草稿数据不影响公开网站。发布在数据库事务中生成不可变快照、版本、媒体引用和审计记录；事务成功后精确刷新相关路径缓存。

### 6.2 安全回退

导航、页脚、首页模块和产品自由页面只在存在合法已发布快照时启用；缺失、损坏、未知 Schema 版本或已归档时回退到现有生产内容，不返回空页或 500。

### 6.3 结构化自由编辑

页面以受 Schema 验证的 JSON 文档保存。编辑器支持拖拽、键盘移动、复制、删除、隐藏和响应式覆盖，但不允许原始代码。内容、布局、样式、媒体、响应式和 SEO 使用受控字段。

### 6.4 真实业务数据绑定

产品分类、型号、参数、相关产品、新闻、发货记录和询盘组件不重复维护一份静态数据，而是通过受控绑定从对应业务模型解析。发布时将解析结果写入快照，避免业务表后续修改绕过页面发布流程。

## 7. 导航、页脚与 URL 策略

### 7.1 公开导航

- HOME → `/`
- ABOUT ZYRON → 保留当前 `/factory`，后台显示名称可配置。
- PRODUCTS → `/products`，下拉继续显示现有八大分类及子类。
- SUPPORT → 包含 Company News 与 Shipping Highlights。
- CONTACT → `/contact`。
- Quote Now 继续使用现有询盘入口。
- 语言菜单在真实本地化 URL 未发布前不伪造跳转，可明确显示“筹备中”或只展示已发布语言。

### 7.2 历史 URL

- `/news` 保留，Buying Guides 只从导航移除，不删文章。
- `/cases` 在发布 Shipping Highlights 列表前继续显示原内容。
- 新的标准路径为 `/shipping-highlights` 与 `/shipping-highlights/[slug]`。
- 当新列表页完成且 SEO 验收后，`/cases` 采用 308/301 永久重定向到 `/shipping-highlights`；如旧 `/cases` 存在独立收录内容，则先制定逐条映射，不做无意义集中跳转。
- 产品 Slug 继续锁定，设计器不得修改产品 URL。

### 7.3 后台导航模型

新增版本化导航文档，表达 Header、Mobile、Footer 及语言可见性。节点包含稳定 ID、父节点、名称、内部或受控外部链接、排序、可见性、打开方式、语言和发布状态。发布前验证内部路径、产品分类绑定和循环层级。

## 8. 前台设计系统

### 8.1 品牌令牌

- Header / 主深色：`#0B0D10`
- Brand Green：`#76B900`
- Dark Surface：`#1A1D21`
- Light Background：`#F5F6F8`
- Dark Text：`#14171A`
- White Text：`#FFFFFF`

使用浅灰、冷白、深钛灰轮换分隔长页章节。大屏优先使用大幅真实设备图与简短文案，移动端保持主体完整、单列阅读和 44px 最小触摸区。

### 8.2 动效和性能

- 只在视口内启动渐入、位移和轻量视差，不阻塞首屏。
- 遵守 `prefers-reduced-motion`。
- 首屏图像按需预加载，非首屏媒体懒加载。
- 手机端视频默认使用封面与用户触发，不自动下载大文件。
- 表格只在自身容器横向滚动，整个页面不产生横向溢出。

## 9. 首页数据绑定

首页继续使用现有 Page Builder 作为基础，逐区转换，不一次性删除硬编码回退。目标模块包含：

1. Hero Banner：复用 Banner 发布与 PC/Tablet/Mobile 媒体字段，增加受控视频、对齐和蒙版。
2. 八大产品系列：从已发布 `ProductCategory` 读取，不复制静态数组。
3. 重点设备：绑定已发布 Product，允许覆盖展示文案与背景。
4. 制造能力、产品优势、应用行业：结构化内容，数字与认证字段不得无来源生成。
5. 发货集锦：从已发布 Shipping Highlights 按日期读取。
6. 新闻：在独立 NewsArticle 模型建立前，保留现有 `/news` 数据回退。
7. 询盘转化：复用现有 Inquiry API 和埋点，不建第二套提交逻辑。
8. 页脚：使用已发布页脚快照，无快照时保留当前 Footer。

## 10. 通用页面编辑器

### 10.1 编辑器布局

- 左侧：组件库、模板、页面结构树。
- 中间：真实渲染规则的 Desktop / Tablet / Mobile 预览画布。
- 右侧：内容、布局、样式、媒体、响应式和 SEO 属性。
- 顶部：设备切换、撤销、重做、保存状态、预览、版本、发布。

### 10.2 文档与树操作

- 使用稳定节点 ID 表达页面树。
- 支持新增、拖拽、键盘移动、跨容器移动、复制、删除、隐藏和排序。
- 拒绝节点移入自身后代、重复 ID、未注册类型、非法 URL、超出深度与数量上限的文档。
- 自动保存与手动保存使用串行队列和乐观锁，发布、回滚或应用模板前排空旧任务。
- 预览路由后台 Session 保护并设置 `noindex`。

### 10.3 组件范围

继续使用现有注册表，优先补齐 Hero、图文、全宽媒体、视频、产品分类/推荐、画廊、卖点、参数表、型号对比、应用、制造能力、发货、新闻、时间线、FAQ、联系、询盘、CTA 和结构化富文本。

布局容器允许 Section、Row、Columns、Grid 和 Stack，并设置 6 层嵌套、200 节点/页、40 直接子节点/容器的上限。

## 11. 产品自由页面

产品页面遵循已有 `docs/superpowers/specs/2026-11-16-zyron-product-page-builder-design.md` 的独立文档方案，新增与 Product 一对一的 `ProductPage` 和不可变 `ProductPageVersion`。

公开路由选择顺序：

1. 已发布产品存在合法 `ProductPage.publishedContent` 时，渲染自由页面。
2. 无自由页面快照时，继续执行现有独立 React 页或 `StandardProductPage`。
3. 仅在现有环境开关允许时使用 legacy catalogue 回退。
4. 全部不存在时才返回 404。

“沉浸式产品故事模板”借鉴 L05 的“吸顶子导航 → 全屏媒体 → 多章图文 → 配置/参数 → 信任与转化”节奏，但使用 ZYRON 设计令牌、真实机械媒体、型号参数和 B2B 询盘动作。小型电动剪板机是首个完整验收实例，但不自动替换当前线上页面。

## 12. Shipping Highlights

### 12.1 核心数据

`ShippingHighlight` 包含标题、Slug、发货日期、国家代码、城市、产品分类、产品、设备名称、型号、数量、装柜、运输、包装、摘要、正文、封面、状态、发布时间、SEO 和版本。`ShippingMedia` 绑定现有 MediaAsset，并区分装柜照、设备照、视频、封面与排序。

客户联系方式、完整地址、物流单号、私人身份与未获授权商标不得公开。国家在数据库保存 ISO 代码，后台按当前中文管理界面显示中文国名，前台按页面语言显示本地化国名。

### 12.2 发布与空状态

发布校验必须包含标题、发货日期、国家、设备、至少一项真实媒体和 SEO 摘要。没有已发布数据时，前台显示不带虚构案例的空状态。列表支持国家、设备类型和时间排序，详情页支持图集与视频。

## 13. 多语言与 SEO

多语言采用“主内容 + 语言变体”，而非复制整个业务对象。`LocalizedContent` 保存实体类型、实体 ID、locale、受支持字段、翻译状态和版本。只为已发布且有实际 URL 的语言输出 hreflang。RTL 使用文档 `dir` 和逻辑方向样式，不用左右写死的绝对定位。

SEO 继续以 `SeoRecord` 为主数据源，扩展 locale、hreflang 关联、图片 alt 完整度与结构化数据警告。`RedirectRule` 保存来源、目标、状态码、启用状态、来源原因和审计信息，发布前检测循环、链式跳转和不存在的内部目标。

## 14. 媒体库

复用现有 MediaAsset、MediaReference 和 S3-compatible 存储，分阶段增加：

- 批量上传与队列进度。
- 图片/视频/文件类型与产品分类筛选。
- alt、尺寸、大小、焦点和视频封面。
- Desktop / Tablet / Mobile 变体关系。
- 替换时保留旧资产与发布版本引用。
- 删除前显示引用位置；仍被草稿、发布快照或保留版本引用时只能软归档。
- 图片转 WebP/AVIF 只生成派生资产，不覆盖或删除原图。

## 15. 权限、API 与可靠性

- 管理员：用户、权限、发布、回滚和系统设置。
- 编辑员：内容、产品、媒体和草稿，是否可发布由角色权限决定。
- 只读账号：可查看已授权模块，不显示可写操作，API 仍强制拒绝写入。
- 写 API 必须验证 Session、权限、同源、Zod Schema、乐观版本和请求大小。
- 多记录更改使用 Serializable 事务；Prisma `P2034` 转换为 409 而非 500。
- 重要操作写入 AuditLog，不记录密码、Token、数据库 URL 或客户敏感信息。
- 缓存刷新失败不能把已提交数据库事务报告为发布失败，应记录可检索告警并返回“已发布，缓存刷新待重试”。

## 16. 后台信息架构

后台保持中文管理界面，并将内容管理与业务 CRM 明确分组：

- 网站管理：页面管理、导航管理、首页管理、页脚管理。
- 公司介绍：企业介绍、工厂展示、荣誉资质、生产能力。
- 产品中心：分类、产品、型号、参数、详情模板、媒体、关联推荐。
- 支持中心：公司新闻、发货集锦。
- 联系我们：联系方式、联系页面、表单配置。
- 业务管理：询盘、客户、跟进。
- 资源管理：图片、视频、文件。
- SEO 与多语言：页面 SEO、翻译、URL 与重定向。
- 系统管理：用户权限、操作日志、发布记录、版本回滚。

菜单项只能在存在可用页面和真实功能时启用，未完成功能不以空白页占位。

## 17. 数据模型边界

在现有 Schema 上扩展，不重建数据库。预计新增或扩展：

- `NavigationDocument` / `NavigationVersion`：导航草稿、发布快照和版本。
- `FooterDocument` / `FooterVersion`：页脚内容与版本。
- `ProductPage` / `ProductPageVersion`：产品自由页面。
- `ProductPageTemplate`：内置与后续管理的产品页模板。
- `ShippingHighlight` / `ShippingMedia` / `ShippingHighlightVersion`：发货内容与媒体。
- `LocalizedContent`：受支持实体的语言变体。
- `RedirectRule`：受审计的 URL 重定向。
- `MediaAsset` 增加变体、焦点、视频封面与文件类型字段，在保持旧数据可读的前提下分步迁移。
- `SeoRecord` 在不破坏现有 pathname 唯一规则前提下设计 locale 索引迁移。

每个迁移必须具备现有数据安全的默认值、前向部署顺序和回滚策略。先在隔离测试库执行 `prisma migrate deploy`，再进入 Preview。

## 18. 分阶段实施

### Phase 0：基线与保护

- 以当前生产 `main` 为基线建立独立工作树。
- 记录路由、导航、产品数量、已发布数据与 SEO 基线。
- 建立未转换内容的兼容测试。

### Phase 1：导航统一与发货集锦

- 先更正现有静态导航，使桌面、移动和 Footer 符合新结构。
- 实现导航数据模型、API、后台管理、发布和前台回退。
- 实现 Shipping Highlights 模型、后台、前台、筛选、SEO 和空状态。

### Phase 2：前台设计系统与首页

- 统一颜色、字体、间距、媒体容器和轻量动效。
- 逐区将首页转换为已发布数据优先、现有内容回退。
- 完成页脚管理与发布快照。

### Phase 3：产品自由页面设计器

- 实施 `ProductPage` 和递归页面文档。
- 复用现有 24 种产品模块，允许重复和嵌套。
- 实现沉浸式产品故事模板与小型电动剪板机验收实例。
- 未转换产品保持现有 HTML、Metadata 和结构化数据。

### Phase 4：通用页面编辑器完整化

- 把现有 Page Builder 扩展为三栏、递归结构树、受控属性面板。
- 增加撤销/重做、模板、未保存提示、三端独立媒体和版本对比。
- 逐步接入 About、Contact 和支持内容，不强制批量迁移。

### Phase 5：多语言、SEO 与媒体增强

- 实现 LocalizedContent、语言发布状态、RTL 与 hreflang。
- 实现 RedirectRule、链接校验、SEO 完整度和结构化数据检查。
- 完成媒体批量上传、变体、焦点、封面与引用位置。

## 19. 测试与验收

每个 Phase 都使用 TDD 实施，并在阶段末执行：

- `prisma validate` 和 `prisma generate`。
- `npm run typecheck`。
- `npm run lint`。
- `npm test`。
- `npm run test:integration`，仅使用隔离测试数据库。
- 相关 Playwright E2E，包含权限、草稿隔离、发布、回滚、旧内容回退和询盘。
- `npm run build`。
- `vercel build` 与 Vercel Preview。

浏览器验收覆盖 1440px 桌面、768px 平板和 390px 手机，检查导航、图片裁切、视频、表格、键盘操作、焦点、对比度、横向溢出和 reduced-motion。

## 20. 部署与生产边界

1. 所有开发在独立 `codex/` 分支与工作树进行。
2. 每个数据库迁移先在测试库执行和回归。
3. Preview 使用安全的 Preview/测试数据库，不在可修改流程中指向生产库。
4. 每个 Phase 提供 Preview 地址、测试账号和验收清单。
5. 生产迁移、合并 `main` 和发布生产必须在该 Phase 完成 Preview 验收后获得单独明确授权。
6. 生产发布后验证首页、产品列表、小型电动剪板机、未转换产品、发货列表/详情、后台登录、管理 API、询盘、Sitemap、Robots 和静态资源。

## 21. 成功标准

- 前台桌面、平板、手机和 Footer 不再出现 Buying Guides 与独立 SHOWCASE，Support 显示 Company News 和 Shipping Highlights。
- 导航发布后前台同步，草稿不改变线上导航。
- 八大产品系列和现有产品 URL 完整保留。
- 管理员可创建、预览和发布真实 Shipping Highlight，无真实数据时不显示假案例。
- 管理员可为任意产品从模板、空白页或其它已发布产品创建独立页面。
- 页面支持重复组件、递归布局、三端媒体/布局、真实参数、询盘绑定和 SEO 状态。
- 草稿、发布快照、回滚和历史版本不互相覆盖。
- 未转换页面与产品的 HTML、Metadata、结构化数据和询盘行为与基线一致。
- TypeScript、Lint、单元测试、集成测试、E2E、Next.js 生产构建与 Vercel Preview 全部通过。

## 22. 已作出的设计决定

- 采用渐进式升级，不大爆炸替换。
- 导航、页脚、通用页面和产品页使用各自明确身份模型，可共享文档校验、版本与编辑器基础，不用 Slug 约定强行绑定。
- 产品自由页面只在存在已发布快照时接管公开路由。
- Shipping Highlights 是独立内容类型，不把原客户案例伪装为发货记录。
- 国家使用 ISO 代码存储，管理界面显示中文，公开页按 locale 显示。
- 多语言使用实体语言变体，不复制业务实体。
- 生产迁移与发布保留单独授权门。
