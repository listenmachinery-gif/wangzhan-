## 安全、兼容和部署风险

- Git 分支曾明显分叉：`origin/main` 不包含已经部署到生产的 CRM/SEO/会话修复，生产代码位于 `codex/fix-vercel-prisma-generate`。本分支已以生产支线为基线，后续应先统一 Git 主线，避免回滚已上线功能。
- 首页、分类和多数产品详情仍引用 `data/` 与独立 React 组件。直接用空数据库页面替换会造成内容和 SEO 丢失，必须采用“已发布数据优先、现有内容回退”的逐步迁移策略。
- 首页的企业实力与选择理由已受 Page Builder 管理；证书、展会和部分 CTA 仍保持现有硬编码回退，后续应逐区迁移。
- `ProductSection` 的 `@@unique([productId, type])` 与 CMS 2.0“重复添加同类模块”冲突，需在产品模块迁移阶段单独变更并提供数据验证。
- 测试数据库并行执行会触发 `pg` 的已弃用并发查询警告；当前测试串行且通过，但应在升级到 pg 9 前消除共享客户端并发用法。
- 本地 worktree 会让 Next.js 推断到父级锁文件并产生警告，不影响 Vercel 构建；可在后续配置 `outputFileTracingRoot` 消除。
- 任何 Prisma 迁移必须先在测试库执行；本阶段不写入生产数据库、不部署生产。

## Phase 0 结论

当前基础系统没有阻止 Phase 1 开发的构建错误。最高优先级是统一版本基线并补齐 Page Builder 的数据库、权限、服务、API、后台编辑器与前台发布读取链路。实现必须保留现有首页作为零数据回退。
